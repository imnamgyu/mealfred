거버넌스 · 세션 인프라 명세 (정본) · v2 2026-08-18

세션스타트 훅 — 컨텍스트 자동 주입,
확실히 보장되는 건 앞 2KB뿐

매 세션 시작 때 Claude에게 위키 인덱스·lint·최근 일지를 자동 주입하는 훅의 구조 명세. 출력이 크면 하네스가 전문을 파일로 빼고 앞 2KB 프리뷰만 인라인 주입한다는 사실이 확인되어(2026-08-18 실측), "2KB 코어 다이제스트 + 반감기 전문" 구조로 개편했다.

1. 훅은 언제, 어떻게 도는가

① 세션 시작 (Claude Code 실행) ~/.claude/settings.json의 hooks.SessionStart에 등록된 명령이 자동 실행된다 — 우리 등록: sh ~/.claude/hooks/worklog-context.sh (timeout 10초).
↓
② 스크립트가 stdout으로 컨텍스트 생성 위키 인덱스(docs.html 파싱) + wiki_lint.py --quick + 주간 롤업 + 최근 일 파일을 조립해 출력.
↓
③ 하네스의 크기 분기 — 여기가 함정
출력이 작으면전부 인라인으로 Claude 컨텍스트에 주입.
출력이 크면 (실측: 16~21KB)전문을 hook-*-stdout.txt로 저장하고, 인라인에는 앞 2KB 프리뷰만 주입.
↓
④ Claude가 프롬프트를 받기 전, 이 내용이 이미 컨텍스트에 존재 단 ③에서 잘렸다면 잘린 뒷부분은 Claude가 파일을 직접 Read해야만 볼 수 있다 (자동 아님).

2. hook-*-stdout.txt 파일의 규칙

생성 시점세션 시작 직후, 훅 stdout이 인라인 임계를 넘을 때 하네스가 자동 생성. (임계값 자체는 하네스 내부값 — 실측으로만 확인: 21,322B 출력 → 파일 저장 + 앞 2KB 프리뷰)
위치~/.claude/projects/<프로젝트>/<세션ID>/tool-results/
이름hook-<호출UUID>-stdout.txt — 세션·호출마다 UUID가 달라져 매번 새 파일
내용훅 stdout 전문 (인라인에서 잘린 부분 포함 전체)
읽는 법Claude에게 "훅 전문 파일 열어봐"라고 하면 Read로 열람. 세션 시작 시스템 메시지에 경로가 찍혀 있다

3. v2 출력 구조 — 2KB 코어 + 전문

순서가 곧 보장이다. 앞 2,000B는 스크립트가 예산으로 강제하는 코어 다이제스트, 그 뒤는 잘려도 파일로 보존되는 전문.

🅰 코어 (≤2,000B · 인라인 보장)

1규칙 1줄 — 위키 정본 먼저·산출물은 위키 게시 마감 (헌법·가정레지스터 포인터)
2lint/review 상태 — high·med·low 건수 + review 대기 (v1에선 맨 아래라 늘 잘리던 것 → 승격)
3최근 일지 반감기 요약 — 아래 §4
4위키 섹션별 카드 수 — "투자 9 · 그로스 7 · …" (전체 목록은 전문에)

예산 초과 시 줄 단위로 아래부터 탈락 — 우선순위 위쪽이 항상 생존.

🅱 전문 (프리뷰 밖 · 파일 보존)

1위키 전체 카드 인덱스 (≤6KB)
2lint 상세 (이슈 목록 + review 큐 항목)
3최신 주간 롤업 (≤4KB)
4최근 3일 일 파일 — 반감기 캡 적용 (아래 §4)

전문 시작 지점에 마커 한 줄: ---(이하 전문 · 인라인 프리뷰 밖 — 잘렸으면 hook-*-stdout.txt에서 읽기)---

4. 반감기(LRU) 규칙 — 최근일수록 풍성, 오래될수록 흐릿하게

사람 기억처럼: 방금 한 작업은 세밀하게, 오래된 작업은 제목만, 더 오래된 것은 존재만 남긴다.

코어 다이제스트의 반감기 (일지 요약)

가장 최근 작업일
세션 제목 전부 (병행 세션 포함)
2~3번째 작업일
첫 세션 제목 한 줄 (80자)
4번째 작업일
날짜만 "…"
그 이전
주간 롤업 포인터 1줄

전문의 반감기 (일 파일 주입 캡)

최신 일 파일
5,000B (머리 3,000 + 꼬리 2,000)
2번째
2,500B (1,800 + 700)
3번째
1,200B (머리만)
4번째~
0B — 주·월 롤업으로만

꼬리를 보존하는 이유: 일 파일은 append 전용이라 최신 세션이 항상 파일 끝에 있다.

💡 설계 원칙: 코어에 넣을 항목의 기준은 하나 — "Claude가 첫 프롬프트를 받기 전에 모르면 사고가 나는 것". 그 외 모든 것은 전문(잘려도 파일에 있음)이나 드릴다운(위키·일지 직접 열기)으로 밀어낸다. 상세 지식 본문은 절대 훅에 넣지 않는다 — 훅은 지도이지 책이 아니다.
