"치매" 근절 계획 (기록 · 회수 · 납품)

증상: 세션마다 맥락을 까먹고, 받은 피드백("PDF 이미지 액자 음영 금지" 등)을 며칠 뒤 같은 유형 작업에서 반복 위반. 탐색 에이전트 3 + 적대 검증 4(반박 렌즈 3 + Claude Code 훅 사양 팩트체크)를 거친 결론: 프롬프트 주입 단층으로는 못 막는다 — 기록·회수·납품 3층 + 이월작업 결정론화로 간다.

3. 설계 — 3층 방어 + 이월 결정론화

🖊 1층 · 기록

결정론 (훅이 강제)

지적 패턴("하지 마·왜 또·금지")을 훅이 감지해 승격 대기 큐에 자동 적재. 누락이 조용히 사라지는 대신 시끄럽게 남는다 — 코어가 "미승격 지적 N건"을 해소까지 매 세션 표시.

📤 2층 · 회수

결정론 (훅이 주입)

작업 유형 키워드 + 프로젝트명 매핑 매칭 시 규칙 카드를 그 자리에서 읽어 ❌규칙 주입(stale 원리적 불가). 첫 매칭은 전문, 같은 세션 재매칭은 1줄 — 소음 방지와 컴팩션 내성 양립.

✅ 3층 · 납품

게이트 (산출물 대조)

보고 전 산출물을 렌더해 카드 ❌항목과 대조 — 재사용 자산 포함. 기억이 아니라 산출물을 검사한다. 훅이 못 잡는 파생 작업·서브에이전트의 최종 방어선.

⏳ +이월작업 결정론화: "다음 세션에 X할 것"은 서사 일지 금지 → review.json에 carryover 타입으로 적재, 해소될 때까지 SessionStart 코어가 매 세션 주입. (08-14 사고의 절반이 이월 TODO 유실이었다.)

4. 실행 계획 P0~P5

P0작업규칙 카드 신설 — 편식극복키트/00_작업규칙/ (학술 백과사전 00_설계원칙과 도메인 분리 · lint SCAN_DIRS 추가). 사고 이력 실재하는 3~5장만 먼저: 발표자료-이미지(폰 프레임·액자 음영) · 구글닥스-편집(fresh read·클립보드 충돌) · 납품-게이트(공통 마감 조항). 형식 = front-matter(키워드·프로젝트 매핑) + 규칙 ID(W-001…) ❌/✅ 불릿 + 근거 일지 링크. 서사 금지 · 4KB 캡. 각 카드를 MEMORY.md 피드백 섹션에 한 줄 등재(검증된 채널). 스킬 있는 유형은 SKILL.md가 정본(카드는 포인터) — 이중 관리 금지
P1UserPromptSubmit 훅 신설 — 0단계: 스텁으로 stdin 스키마 실측(문서 상충 해소). 기능 A = 지적 감지기(1층) · 기능 B = 규칙 주입(2층, 2축 매칭 — 단일 저정밀 키워드 금지). 매칭/미매칭 전량 로그 → 2주 데이터로 키워드 튜닝. 서브에이전트는 훅이 못 잡음을 명세에 정직 기재(3층이 받침)
P2SessionStart 훅 v3 최소 수술 — 코어에 행동 강제 상태만 추가(미승격 지적 N건 · 이월작업 N건 — "필독" 류 훈계문은 예방가치 0 판정으로 배제). 안정화 3건: timeout 10→30 + lint 시간 가드 폴백 + tmp 정리. 실행본↔정본은 사본 유지 + 해시 불일치 시 코어 1줄 경고(심링크는 iCloud 축출 리스크로 대안). 나머지 8건 결함은 이론적·장식으로 보류
P3이월작업 결정론화 — review.json carryover 타입 정식 편입 + 겸사 스키마 정규화(type 통일·만료 일괄 close로 경보 총량 실감축) + lint 스키마 검증
P4MEMORY.md 수술 + 재증식 방지 — 13개 비대 불릿을 topic 파일로 기계적 이식(요약 금지 — 뉘앙스 유실 방지, "충돌 시 인덱스 승리" 명기). 인덱스에는 구조화 핫스테이트 포인터만: [상태·D-day·정본 fileId·다음 액션·블로커] ≤200자 — 마감 정보는 인덱스 잔존(신선도 역전 방지). 정정은 [정정 YYYY-MM-DD] 마커 병기(원문 삭제 금지). lint 신규 3종: memory-index-bloat(줄>250자·총량>10KB — worklog 마감 채널로만 소비, 코어 소음 금지) · 카드↔인덱스 정합 · feedback_* 신규 생성 감지
P5거버넌스 마감 — WIKI.md 조항(지적 즉시 승격 · 이월 큐 · 단일소스 컴파일 · SKILL.md 우선순위 · [정정] 마커) + /mealfred-worklog 마감 확장(미승격 큐 소진·오매칭률 보고·bloat 집도) + 훅 명세 v3 개정 + task-rules.html은 카드에서 자동 컴파일(수동 사본 금지) + 카드 등록 + 양 레포 커밋

5. 검증 — 수용 기준은 "주입이 떴는가"가 아니다

1프롬프트 코퍼스 회귀 셋 — 실사고 재현("발표자료 PDF에 이미지") · 프로젝트명만("모두의창업 v9.4 마무리") · 승인형("네 진행해" — 스티키로 커버) · 네거티브("PDF 읽어줘" — 침묵 확인). 매칭률 <70%면 키워드 재설계
2지적 감지 — "왜 또 액자 넣었어" 스텁 입력 → 승격 큐 append → 다음 세션 코어에 건수 표시
3새 세션 실기동 — 코어 2KB 생존 · 세션 중간 파생 작업 프로브("그거 슬라이드로도 만들어줘")
4MEMORY 이식 후 "원문 바이트가 topic에 존재" 자동 대조 · lint 신규 체크 발화/해소
★최종 수용 기준: 새 세션에서 발표자료 이미지 작업을 지시했을 때, 산출물에 폰 프레임/액자 음영 규칙이 실제 적용되고 보고 전 카드 대조가 수행되는가

6. 결정 대기 (이사님 3건)

1주입 강도 — 추천: 첫 매칭 시 카드 ❌불릿 전문 주입(fresh read라 항상 최신 · 컴팩션 내성) / 대안: 제목+경로+개정일만(토큰 절약)
2MEMORY 수술 범위 — 추천: 13개 전면(기계 이식 절차 전제) / 대안: 최악 3줄(7.9K·6.4K·3.0K)만 1주 파일럿 후 확대
3실행 순서 — 추천: P0~P5 한 번에(1~2세션) / 대안: 카드+MEMORY 수술 선행 출고 → 2주 재발 데이터로 훅 필요성 재판정(효과 귀속은 명확해지나 봉합이 늦어짐)
